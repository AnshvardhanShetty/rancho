# Running the recorded SSD algorithm

Install the repository's Python requirements. Building the native tools also requires a C++17 compiler, OpenSSL headers and `pkg-config`.

From the repository root:

```bash
make -C ssd/replay recorded-support
python -m unittest discover -s ssd/algorithm/tests
python ssd/algorithm/tests/check_policy.py
python ssd/algorithm/tests/check_pipeline.py
```

These commands build the replay and supporting tools and run synthetic checks. No private input is needed. The complete-pipeline check creates synthetic labels and histories to test the software connections; it does not measure model quality. `check_policy.py` compares against outputs generated by the hash-matched reconstructed source.

## Run with authorized prepared inputs

The full runner starts with prepared input files. It does not download a trace or manufacture training labels.

```bash
python -m ssd.algorithm.run --manifest /path/to/prepared-inputs.json --output /path/to/new/output --ssd-blocks BLOCK_COUNT --budget-blocks WRITE_ALLOWANCE
```

The output directory must be new. Capacity and allowance are counts of blocks, not bytes. The recorded GPU-cache allocation is 81,380 blocks. The replay uses days 4–7, seed 17 and the registered model/controller recipe. It does not search for alternative settings.

The manifest contains:

- `files`: checked records for `timestamps`, `evictions`, `features` and `sample_indices`.
- `eviction_count`, `ntrain`: total eviction count and the number before the measured-cache reset.
- `feature_schema`: the supplied input encodings, including which values are categories.
- `cumulative_labels`: a checked 169-by-sample-count array of observed marginal gains, stored as little-endian unsigned 32-bit integers. Row h contains gains observed strictly before hour h.
- `replay`: checked `block_ids`, `block_counts`, `arrival_times`, `tokens`, `measured_evictions` and `reference_rows`; the block-ID range in `block_id_count`; and `credit` records named `offsets`, `bits` and `ranks`.
- Optional `expected_scores_sha256` and `expected_result`: independently recorded predictions and counts to require exact reproduction.

Each file record contains `path` and `sha256`. Paths may be relative to the manifest. The request stream uses the filename endings described in the [baseline input guide](../replay/README.md). The credit files are `offsets.i64`, `credit.bits` and `credit.rank` in one directory.

The registered full evaluation prediction digest is in `SOURCE_VERIFICATION.json`. Set `expected_scores_sha256` to that value when checking the original full input. A different data preparation, library version or model setting may fail the exact prediction check; investigate rather than replacing the expected value.

The runner trains the 96 hourly models, saves their predictions, and starts the native replay. At each model boundary the native process asks Python to rescore earlier offers. The runner then checks the write log with the independent C++ checker and applies the same-conversation index to obtain the recomputation count. Only models created in that output directory are loaded by this command.

## Build the observed labels

`support/label_replay.cpp` follows a supplied reference write log and records the contribution of each sampled eviction to later readable input. It needs the same prepared request stream, sampled eviction IDs and checked same-conversation index as the original procedure. New path arguments are `--label-samples`, `--label-credit` and `--label-event-offset`; the offset is zero for the training replay and the earlier eviction count for the measured replay.

Run the reference separately with cold caches over days 1–3 and days 4–7. Keep the original reference decisions and verify the resulting write log and request rows. `labels.build_observed_counts()` turns those two `.gain` streams into the hourly label matrix. It excludes reads exactly at the cutoff and rejects a gain that precedes its offer.

`support/session_accounting.cpp` contains the original index-building and independent index/count checks. Its input is the prepared calendar used by the trace evaluation; it is a supporting tool, not a raw JSONL reader. Raw request conversion and the prepared calendar must preserve request order, block identities, session boundaries and duplicates.

A trained model file or saved prediction vector alone is not enough to reproduce the paper: the request sequence and its eligible-read index are also required. Those inputs remain private.
